## 2025-05-18 - Async UI States and Error Feedback
**Learning:** When dealing with asynchronous operations on lists of items, using a shared global boolean (e.g., `isInvestigating`) for loading states creates a confusing UX where interacting with one item affects the visual state of all items. Furthermore, without explicit error rendering (e.g., in a dedicated container with `role="alert"`), API failures can fail silently, leaving users confused about the result of their actions or assuming false success.
**Action:** Always use unique identifiers (e.g., `investigatingId`) for row-specific loading/disabled states in lists. Always explicitly render error states for asynchronous operations using a container with `role="alert"` to ensure accessibility and prevent silent failures.
